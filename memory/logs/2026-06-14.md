# 2026-06-14 Activity Log

## MCP Authentication Remediation

### Problem
GitHub MCP (`github-mcp-server`) and OctoCode MCP (`octocode-mcp-linux-arm64`) both returned HTTP 401 "Bad credentials" despite valid tokens in gopass.

### Root Cause
`~/.hermes/config.yaml` contained literal shell variable references:
- `GITHUB_PERSONAL_ACCESS_TOKEN: $GITHUB_TOKEN`
- `GITHUB_TOKEN: $OCTOCODE_GITHUB_TOKEN`

Hermes does not expand shell variables in config.yaml.

### Fix
Hardcoded actual PAT values (from gopass) into config.yaml via Python script:
- GitHub: `ghp_xu...BUtC...`
- OctoCode: `ghp_km...rufL...`

Restarted `hermes-gateway.service` → both MCP servers authenticate.

## Multi-Model Cross-Validation

Launched 2 parallel reviews via Venice AI (Qwen 3.7 Max + Plus).

### Consensus Findings
| Area | Finding | Action |
|------|---------|--------|
| Security | Hardcoding PATs bypasses `redact_secrets`, leaves plaintext on disk | Rotate PATs immediately |
| Architecture | Hermes needs `${VAR}` expansion or secret injection in config.yaml | File feature request |
| Operations | systemd + hardcoded config is anti-pattern | Use `EnvironmentFile` + gopass |
| Verification | API tests don't prove secret containment | Check swap/core dumps/VCS |

### Recommendations (Both Models)
1. Revoke current PATs, generate new ones
2. Create `~/.hermes/secrets.env` (chmod 600) populated by gopass
3. Update systemd service: `EnvironmentFile=~/.hermes/secrets.env`
4. Request Hermes `${VAR}` expansion support upstream
